ViSiOCR

A two-role visitor management system where users register visitors, extract government ID details with OCR and generate QR-based passes, while admins scan and validate passes.

About 80% less manual entry time, with more accurate data for security checks.

  • Python
  • Django
  • Tesseract OCR
Project overview ↗

Two user roles

1. User

Logs in, enters the visitor's visit date, time and duration, then uploads a government ID. OCR extracts the available ID details for review and pass creation.

2. Admin

Logs in to the admin view, scans the visitor pass QR code and validates the pass before allowing entry.

End-to-end flow

  • User login and visitor information entry.
  • Choose visit date, time and duration.
  • Upload a government ID; OCR extracts the text into structured fields.
  • Generate a visitor pass containing a unique QR code.
  • Admin scans the QR code to check and validate the pass.

Core value: Reduces manual visitor registration and makes entry verification quicker.

Fake News Detection

A news-checking app where logged-in users upload or enter an article and receive a fake/real prediction score using text analysis and a Logistic Regression classifier.

95% accuracy on a standard benchmark dataset.

  • Python
  • Scikit-learn
Project overview ↗

User workflow

  • User logs in to the application.
  • Uploads a news article or enters its text.
  • The system preprocesses the text using a text-processing pipeline.
  • A machine-learning classifier analyzes the content and returns a fake/real prediction with a score.
  • The result helps the user decide whether to investigate the article further.

How it works

Text preprocessing: Cleans and prepares the article text using NLTK.

Classification: Uses the Logistic Regression model to estimate whether the submitted article resembles the fake or reliable examples in its training data.

Result: Displays the predicted label and model score. This is an automated prediction, not a guarantee of factual accuracy; users should verify important claims with trusted sources.

Notes

Two short write-ups on how I build and what the internships taught me.

Project note

How I wired the transcript summarizer

The app is a small Flask service with a login, one form, and a result page. A signed-in user pastes a YouTube URL. The server pulls the available transcript, sends that text to the Google Generative AI API, and stores a short summary the user can read immediately.

Follow-up questions stay useful only if the model still sees the summary. I keep that summary in the request context instead of asking the model to remember the video. If a video has no transcript, the page says so instead of inventing one. The hard part was not the summary itself. It was keeping login, transcript fetch, and the question box as separate steps so a failure in one does not blank the whole page.

Internship note · Infosys Springboard, 2024

What I learned splitting a Django app

On the Python stack internship I stopped putting every view, query, and template trick in one file. Database-backed pages were easier to review once each feature had its own module and the template only rendered what the view passed in.

Agile standups and GitHub reviews changed how I write. A branch per task, a short pull request, and a teammate reading the diff caught bugs I had already stopped seeing. That habit is what I still use on ViSiOCR and the fake-news classifier: small pieces, a clear data path, and someone else able to run it.
